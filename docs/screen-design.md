# 読書記録アプリ 画面設計書

- 作成日：2026-11-20
- 更新日：2026-11-23
- ステータス：実装仕様書
- 対象：読書記録アプリ `book-list`
- 関連資料：`docs/system-requirements.md`、`README.md`、初期ワイヤーフレーム4枚
- 本書は現行UIの画面構成・操作・表示状態を定義する。実装状況は関連コードで確認する。

## 1. 目的と基本方針

読書記録の**閲覧を中心**に据え、必要なときに登録・詳細確認・編集・削除ができるアプリを目指す。

- ホーム画面には情報を詰め込みすぎず、読書状況と最近の記録を見せる。
- 入力フォームは常時表示せず、「記録を追加」ボタンから開く。
- 一覧には必要最小限の情報を表示し、メモなどは詳細モーダルにまとめる。
- 記録件数の増加に備え、全件一覧は20冊ずつ取得・表示する。
- 新規登録・編集に共通のフォームを使えるようにする。
- ユーザー向け画面から開発・運用向けの接続状況表示を整理する。
- 現行のReact / TypeScript、Cloudflare Workers、D1、R2、Better Authを基本的に維持する。
- 既存のログイン・ユーザー別データ管理・写真保存の仕組みを壊さない。
- 認証・保存先・セキュリティなどのシステム要件は `docs/system-requirements.md` を参照し、本書では画面・操作・表示状態を中心に規定する。

## 2. ワイヤーフレームと画面構成

初期ワイヤーフレームは `docs/` に次のファイル名で配置する。画面の基本構成を参照し、現行UIと異なる配置・操作は本書を優先する。画像内の冊数・日付・書名は例示データであり、画像上の「…」は同形式の行の省略表現であって実画面には表示しない。

| 対象 | 画像ファイル |
| --- | --- |
| ホーム（通常時） | `ワイヤーフレーム_ホーム画面_通常時.png` |
| 全件一覧 | `ワイヤーフレーム_全件一覧.png` |
| 新規登録モーダル | `ワイヤーフレーム_新規登録モーダル.png` |
| 詳細モーダル | `ワイヤーフレーム_本の詳細モーダル.png` |

編集モードは新規登録フォームを共用するため、専用のワイヤーフレームを設けない。登録済みの値や写真プレビューを表示し、「キャンセル」「保存する」を備える。

※初期ワイヤーフレームの詳細画面のボタン配置は現行UIと異なる。現行UIでは「編集」を右上、「閉じる」を下部中央に配置する。写真変更の確認とトースト通知も本文の記述を優先する。


| 画面・UI | 役割 | 表示方法 |
| --- | --- | --- |
| ログイン・新規登録 | ユーザー認証 | 既存の認証画面を維持。公開中は新規登録画面に受付停止の案内を表示し、登録ボタンを無効にする |
| ホーム | 読書状況と最近の記録を確認 | メイン画面 |
| 全件一覧 | 登録済みの本を探す・選ぶ | ホームから移動する画面 |
| 新規登録 | 読書記録を追加 | モーダル |
| 詳細 | 1冊の情報とメモを確認 | モーダル |
| 編集 | 詳細から既存の記録を変更 | **同一モーダル内で編集モードへ切り替え** |
| 削除確認 | 誤操作を防ぎつつ削除 | 確認ダイアログ |

ホームと全件一覧は「すべて見る」「ホームに戻る」で移動する。URLルーティングの新規導入は必須としない。

### 基本的な操作の流れ

```text
ログイン
  └─ ホーム
      ├─「記録を追加」→ 新規登録モーダル → 登録成功 → ホーム更新
      ├─ 最近の記録（最大5冊）を選ぶ → 詳細モーダル
      │    ├─「編集」→ 同じモーダルで編集モード → 保存 → 詳細表示に戻る
      │    └─「削除する」→ 削除確認 → 削除成功 → モーダルを閉じ一覧更新
      └─「すべて見る」→ 全件一覧（20冊ずつ）
           ├─ 記録を選ぶ → 詳細モーダル（編集・削除も可能）
           └─「ホームに戻る」→ ホーム
```

## 3. ホーム画面

### 表示項目と配置

- ヘッダー左にアプリ名、右にログインユーザー情報とログアウトボタンを置く。
- ヘッダーの下に「＋ 記録を追加」、登録総数、今年の読了数を横並びに置き、**追加ボタンを最も大きく目立たせる**。集計カード2つは控えめなサイズにする。
- 下段は「最近の読書記録」と、その右側の「すべて見る」。最近の記録は縦方向の行で表示する。
- 集計の単位は「冊」で統一する。

表示項目：

1. アプリ名「読書記録」
2. ログインユーザー情報とログアウト操作
3. 目立つ位置に「＋ 記録を追加」ボタン
4. 登録した本の総数
5. 今年の読了数
6. 「最近の読書記録」最大5冊
7. 「すべて見る」リンク／ボタン

### 最近の記録1件に表示する情報

- 小さな表紙画像（ない場合は共通のプレースホルダー）
- タイトル（未登録なら「タイトル未登録」）
- 作者名（未登録なら「作者：未登録」）
- 読了日（入力されている場合のみ）
- 詳細を開ける操作領域

**メモはホームには表示しない。** 写真のアップロード・差し替え操作もカード上には置かない。

### 件数・並び順の定義

- 「登録した本」＝ログインユーザーの読書記録総件数。
- 「今年の読了数」＝読了日が入力されていればその年が日本時間の現在の年に属する記録件数。読了日未入力（`NULL`・空文字）の記録のみ、登録日時を日本時間に換算して当年か判定する。
- 「最近の読書記録」＝**登録日時 `created_at` の新しい順**で最大5件。読了日の新しい順とは区別する。
- 件数表示のために全件の書籍レコードを取得せず、集計用クエリで求める。

### 状態ごとの表示

- 記録0件：「まだ読書記録がありません」＋「記録を追加」への案内。
- 読み込み中：読み込み表示。
- 取得失敗：失敗した旨と「再読み込み」を表示。「0件」と誤表示しない。
- 登録成功：モーダルを閉じ、件数と最近の記録を更新し、画面上部のトーストで通知する。

## 4. 全件一覧画面

### 基本仕様

- 画面上部に「← ホームに戻る」、見出し「全件一覧」、総登録冊数と現在の表示範囲（例：「全80冊｜1〜20冊目を表示」）を配置する。
- **1ページ最大20冊**を縦に並べ、画面を開いたときは1ページ目を表示する。表示領域内に一度に見える行数は端末やズーム倍率により変わる。通常のページスクロールで残りの行を閲覧する。
- ページ番号は現在の20冊の末尾に配置する。ワイヤーフレームの5行と「…」は作図上の省略であり、実際の表示件数を5件に制限しない。
- 各記録はホームと共通のコンパクトなカード／行を使用し、選択すると詳細モーダルが開く。
- ページ切り替えは**「1」「2」「3」…のページ番号ボタン**で行う。「前へ」「次へ」は設けない。
- ページ番号は総件数から `ceil(総件数 / 20)` で求める。1〜20冊なら「1」のみ、21〜40冊なら「1」「2」、80冊なら「1」「2」「3」「4」を表示する。0冊のときも一覧の空状態を表示し、ページ番号「1」を表示する。
- 現在のページ番号は見た目とアクセシビリティ属性で識別できるようにする。
- **どのページ番号へも直接移動可能**とする。例：1→3、4→1。前のページを取得しておく必要はない。
- **API側で指定したページの最大20件だけ取得**する。全件取得後にフロントエンドで20件ずつ切る方式にはしない。
- ページ番号一覧のための**総件数**は書籍本文を全件取得せず、DBで件数を集計して取得する。
- 並び順は `created_at` の新しい順を基本とし、同じ日時の場合は `id` 等の補助キーで安定した順序にする。
- 検索・並び替えは今回の基本実装範囲には含めない。

### ページ指定APIの考え方

- 例：`GET /api/books?page=3&limit=20`。ページ3の場合、DBでは該当する41〜60冊目を取得する。ページ番号は1始まり。
- DBクエリでは検証済みの `limit` と `offset = (page - 1) * 20` を使用し、ユーザー所有の記録に限定する。
- 応答には当該ページの書籍レコードと総件数（または総ページ数）を含める。正確なレスポンス形式は既存APIとの整合性を保って実装する。
- 存在しないページ番号、非数値、0以下などを適切に扱い、DBへ不正な値を渡さない。
- データ件数が増え、ページ数が多くなった場合の番号ボタンの省略表示は将来の拡張範囲とする。現在は全ページの番号を表示できる設計とする。

### ページ移動とデータ変更時の挙動

- ページ番号を押すと、そのページの最大20件のみをAPIから取得して切り替え、一覧の先頭が見える位置へスクロールする。
- 読み込み中はページ切り替え中であることを表示し、失敗時はエラーと再試行を表示する。
- 現在表示中のページの最後の1冊を削除し、そのページが空になった場合は、更新後に存在する最後のページへ移動する（全記録が0冊なら1ページ目）。
- 書籍の追加・削除後は総件数と該当する一覧を再取得し、ページ番号を整合させる。新しい記録を確認させる場合は1ページ目を表示する。

## 5. 新規登録モーダル

### 開き方・閉じ方

- 「＋ 記録を追加」で開く。
- 背景を暗転させ、モーダルの**中心をブラウザの表示領域の上下左右中央**に配置する。幅と最大高さは画面内に収める。
- タイトル直下に常時「※タイトル・作者名・読了日・メモのうち、1項目以上入力してください。写真だけでは登録できません。」と表示する。各入力欄のラベルには「（任意）」を繰り返し表示しない。
- 入力欄はPCでは左にラベル、右に入力部分を揃える。スマートフォンでは縦方向に並べる。
- モーダル内にタイトル「新しい読書記録」と、下部に**「キャンセル」「登録する」の2ボタンのみ**を表示する。右上の「×」ボタンは設けない。
- 「キャンセル」で閉じる。入力済みの内容がある場合は破棄確認を表示する。
- 背景領域のクリックでは閉じない。キーボードによる閉じ操作でも、未保存の内容がある場合は破棄確認を経る。
- モーダルの最大高さは表示領域の約80〜90%を目安とし、長い入力フォームは内部をスクロールできるようにする。「キャンセル」「登録する」はモーダル下部で操作しやすい位置を維持する。
- 登録中はボタンの連打・重複送信を防止する。

### 入力項目

| 項目 | 入力方法 | 補足 |
| --- | --- | --- |
| 本のタイトル | 1行テキスト | 任意 |
| 作者名 | 1行テキスト | 任意 |
| 読了日 | `YYYY`・`YYYY-MM`・`YYYY-MM-DD` をまとめて入力できるテキスト欄とカレンダー選択 | 任意。カレンダー選択時のみ完全な日付に更新し、年・年月を補完しない |
| 本の写真 | 下記の単一選択＋条件付き入力 | 任意 |
| メモ | 複数行テキスト | 任意。既存項目を維持 |

### 写真の登録方法

「本の写真」の欄は、**次の3択の単一選択式（ラジオボタン）**とする。表示順と初期選択は固定する。

1. **写真なし**（新規登録時のデフォルト）
2. **画像ファイルをアップロード**
3. **画像URLを入力**

- 「写真なし」では写真の入力欄を表示しない。
- 「画像ファイルをアップロード」を選択すると、ファイル選択欄を表示する。JPEG・PNG・WebPの元画像は20MiB以下、長辺10,000px以下かつ5,000万画素以下。大きい画像はアップロード前に自動縮小・圧縮する。
- 「画像URLを入力」を選択すると、URL入力欄を表示する。
- **1冊につき有効な写真は1つだけ**とし、アップロードとURLを同時に指定・保存しない。
- 別方式へ切り替えた場合、以前選んだファイル・URLを送信対象から外す。意図しない写真の保存を防ぐ。

### 必須条件と入力検証

- タイトル・作者名・読了日・写真・メモの**個々の項目は任意**だが、新規登録には**タイトル・作者名・読了日・メモのうち最低1項目の有効な入力が必要**。文字列が空白文字だけの場合は入力済みと数えない。写真だけでは登録できない。
- 上記4項目に有効な入力がない状態で「登録する」を押した場合は、写真の指定有無にかかわらず、常時表示の説明文とは別に**「タイトル・作者名・読了日・メモのいずれか1項目を入力してください。」**というエラーを表示し、モーダルを開いたままにする。
- 写真の「写真なし」という選択自体も入力済みとは数えない。写真ファイルや画像URLは、上記4項目の入力条件を満たす記録に追加できる。
- この条件はフロントエンドとWorkerの両側で検証する。形式の不正な日付・URL・ファイルも理由を示して拒否する。

### 登録後の動作

- 登録成功後にモーダルを閉じ、ホームの件数・最近の記録と必要な一覧を更新する。
- 現行の写真付き登録は、書籍登録→写真アップロードの2段階。書籍情報の作成時に上記4項目の有効な入力を検証し、写真だけの書籍レコードは作成しない。
- 写真アップロードだけが失敗した場合は、画面上部のエラートーストで「記録は保存済み、写真のみ失敗」と明示し、「写真を再試行」を表示する。
- 入力・登録エラーではモーダルを閉じず、フォーム内に理由を表示する。入力値を保持する。

## 6. 詳細・編集モーダル

### 詳細表示モード

ホームまたは全件一覧の記録を選ぶと、背景を暗転させ、ブラウザの上下左右中央に「**本の詳細**」モーダルを開く。詳細の構成は次のとおり。

- ヘッダー右上：鉛筆アイコン付きの「編集」を配置する。
- 上段左：一覧より大きい表紙画像（写真がない場合は代替表示）。
- 上段右：「本のタイトル」「作者名」「読了日」の**項目名を小さく、登録された値を大きく**表示する。項目名と値の両方を残す。
- 中段：「メモ」の見出しと、改行を保持したメモ全文を収める枠。
- メモ枠の下：ゴミ箱アイコン付きの「**この記録を削除**」を小さめのリンク風に表示し、右寄せにする。
- 最下段：控えめな白い「閉じる」ボタンを中央に配置する。
- 右上の閉じる×ボタンは置かない。長いメモはモーダル内でスクロール可能にし、操作ボタンを利用できるようにする。

詳細ではタイトル・作者名・読了日の項目名を残し、未登録の値は空欄にする。メモ未登録時も枠内は空欄にする。一覧の代替文言とは表示を分ける。

### 編集モード

- 詳細モーダル右上の「編集」を押すと、**モーダルを閉じずに中身を編集フォームへ切り替える**。
- 新規登録フォームと可能な限り共通のフォーム部品・入力チェックを利用する。
- 編集フォームには保存済みの値を初期表示する。
- 「保存する」で変更内容を保存し、成功したら詳細表示モードに戻して新しい内容を表示する。
- 「キャンセル」で未保存の変更を破棄し、詳細表示モードに戻る。変更があれば必要に応じて確認する。
- 通常の保存失敗では編集画面と入力値を保持し、フォーム内に理由を表示する。書籍情報の保存後に古い写真の後片付けだけが未完了なら詳細表示へ戻して理由を示す。更新成功時は画面上部のトーストで通知する。

### 写真の編集・削除

- 編集フォームでも写真の指定方法は**「写真なし」「画像ファイルをアップロード」「画像URLを入力」**の3択・単一選択とする（同じ順序）。
- 編集を開いた際は保存済みの写真状態に応じて初期選択を設定する。写真がなければ「写真なし」、R2写真があればアップロード、外部URL写真があればURLを選択する。
- 既存写真のプレビューを表示する。アップロード写真はブラウザの制約上、保存済みファイルをファイル選択欄へ自動設定しない。
- 現在の写真を**変更せず**、タイトル・作者・メモなどだけ編集・保存できる。
- 既存写真を別のファイル・URLに差し替えるか「写真なし」で削除して保存する場合は、保存前に「写真の変更を確認」を開く。「編集に戻る」または「変更して保存」を選べる。写真を変更しない保存では確認を挟まない。
- 既存の写真がある状態で「写真なし」を選んで保存すると、**写真だけ削除**し、書籍レコードは残す。写真URL・R2キーを適切にクリアし、R2写真があれば不要なオブジェクトを削除する。
- URLからアップロードへ変更した場合は、URLの保存値をクリアし、アップロード写真を有効にする。
- アップロードからURLへ変更した場合は、アップロード写真の参照を解除してR2オブジェクトを削除し、URLを有効にする。
- 同じ写真登録方法のまま何も再指定しなければ、現在の写真を維持する。「写真なし」の新規選択は削除の意思として扱う。
- 写真の変更・削除に失敗した際は、画面とDB／R2の保存状態が食い違ったまま成功と表示しない。Worker側で新旧の写真の後片付けと部分失敗状態を扱い、画面に理由を表示する。

### 削除

- 詳細モーダル右下寄りの「🗑 この記録を削除」から削除確認を表示する。ヘッダーの「編集」と下部の「閉じる」とは別の操作領域とする。
- 押した直後には削除せず、「この読書記録を削除しますか？」という確認を表示する。
- 成功したらモーダルを閉じ、ホームの件数・最近の記録／全件一覧を更新し、画面上部のトーストで通知する。
- 失敗したら記録を画面上から消さず、詳細モーダル内に理由を表示する。
- D1の書籍情報とR2の写真の削除・失敗時処理をWorker側で扱う。記録削除後に写真の後片付けだけが未完了なら、画面上部のエラートーストで通知する。

## 7. 画像表示とパフォーマンス

- **一覧に小さな表紙画像を残す**。写真は書籍を視覚的に見つける助けになる。
- ホームは最大5冊、全件一覧は1ページ20冊に制限する。
- 一覧の画像は遅延読み込みする。
- 画像がない場合や読み込めなかった場合に備えてプレースホルダーを表示する。
- 現行の非公開R2・Worker経由の写真配信は維持する。
- アップロード前に、長辺1,200pxまたは5MiBを超える元画像を必要に応じて最大辺1,200pxへ縮小・圧縮し、送信画像を5MiB以下にする。収まらない場合はエラーを表示する。一覧専用サムネイルの生成は必要性を測定してから検討する。
- 書籍メタデータと写真本体を分けて扱い、一覧の取得で画像バイナリをまとめて返さない。

## 8. ユーザー情報・接続状況・レスポンシブ表示

### ユーザー領域

- ログイン中のユーザー情報とログアウト操作を残す。
- 現行の「Worker API」「D1 接続済み」「認証：ログイン済み」などの開発・運用向け表示は、通常画面から取り除く。
- 必要な接続確認は開発・運用側で可能な形を維持し、通常ユーザーにはエラー発生時に意味のあるメッセージを出す。
- 公開 `/api/health` は開発・運用用途として扱い、一般利用者に不要な内部環境情報を公開しない。画面から表示を消すこととAPIの削除は分けて扱う。

### 画面サイズへの対応

- PCではホームのサマリーと最近の記録を余裕のある横幅で表示し、コンテンツの最大横幅を設けて過度な横伸びを避ける。
- スマートフォンではカードやボタンを縦方向に配置し、横スクロールを必要としない。
- モーダルは小画面で画面内に収まり、内容が長ければスクロールできるようにする。
- モーダルを開いたら内部へフォーカスを移し、閉じたら元の操作位置へ戻す。キーボード操作も可能にする。

## 9. 入力検証・認証・エラー表示

- フロントエンドだけでなくWorker側でも、文字数・日付形式・URL形式・写真形式・容量・JSONの形を確認する。
- 各入力項目は個別には任意だが、**新規登録時はタイトル・作者名・読了日・メモのうち最低1項目の有効な入力を必須**とする。編集時も保存後にこの4項目の有効な値が最低1つ残るよう検証する。空白文字だけの文字列や形式が不正な値は有効な入力とせず、理由を表示する。
- エラーは「通信失敗」「認証切れ」「権限なし」「入力不正」「写真だけ失敗」など、利用者が理解できる内容にする。
- 未ログインユーザーによる読書記録APIの利用を拒否する。
- 取得・編集・削除・写真操作はいずれもログインユーザー本人の記録かをWorker側で確認する。
- 読み込み失敗時に「記録がありません」と表示しない。
- 削除・編集の結果を取得し直したときにも正しい内容が表示されることを確認する。

## 10. 実装上の留意点

### 現行コード調査で分かっていること

- 画面：`src/App.tsx`、`src/AuthForm.tsx`、`src/BookWorkspace.tsx`
- API：`worker/index.ts`

- データベースの変更履歴：`migrations/`
- 実装済み機能：認証、書籍の登録・詳細・編集・削除、ホームの件数集計と最近5件、全件一覧のページ分け、写真アップロード・差し替え・削除、保存結果の通知。
- 現行の写真付き登録は書籍登録後に写真をアップロードする2段階処理。

※上記の実装済み判定は関連コードの静的確認に基づく。動作結果の保証には個別の確認が必要。

### API・データの実装状況

- `GET /api/books` と `POST /api/books` を維持し、写真だけの新規登録を拒否する条件と写真保存失敗時の扱いを含めている。
- 書籍の詳細取得・更新・削除に認証付きエンドポイントを使用する。
- 全件一覧はページ番号による任意ページへの直接移動に対応し、総件数を別途集計して各ページ最大20件のみDBから取得する。ホームは最新5件と件数集計を取得する。
- `books.updated_at` は要件書にあるが現行DBにはないという調査報告がある。編集時刻が必要なら、既存データを保持する新しいマイグレーションを検討する。
- 既存のマイグレーションファイルを安易に改変・再適用しない。とくに `0003_books_auth_user.sql` は既存データ削除を含むとREADMEに記載されている。
- 仕様決定前に不要なライブラリやルーティング機構を追加しない。
